# Contributing to vMACS

Thank you for your interest in contributing to vMACS!

vMACS is an actively developed Rust terminal editor. Contributions, bug reports, suggestions, and constructive feedback are welcome.

## Reporting Bugs

Before opening an issue:

1. Check whether the issue has already been reported.
2. Include your vMACS version, operating system, and terminal emulator.
3. Describe the steps needed to reproduce the problem.
4. Include relevant error messages or terminal output.

Please avoid including private information or sensitive file contents in reports.

## Suggesting Features

Feature suggestions are welcome. Describe the problem you want to solve, the proposed behavior, and why the change would benefit vMACS.

For substantial changes, consider opening an issue for discussion before implementing them.

## Submitting Changes

1. Fork the repository.
2. Create a branch for your changes.
3. Implement your changes.
4. Test the affected functionality.
5. Submit a pull request describing your changes and the tests performed.

## Development Guidelines

- Keep changes focused and consistent with the existing codebase.
- Follow established Rust conventions and project structure.
- Avoid unnecessary dependencies and complexity.
- Preserve existing functionality unless a change is intentional.
- Pay particular attention to file integrity, saving behavior, and error handling.
- Document new configuration options and commands where appropriate.

## Testing

Test the functionality affected by your changes and check for regressions where practical.

Changes involving file operations should be tested carefully to avoid data loss.

## Questions

For questions or discussions, use the repository's available GitHub issues or discussions.

Thank you for helping improve vMACS!
